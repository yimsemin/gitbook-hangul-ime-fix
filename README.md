# gitbook-hangul-ime-fix

GitBook 편집기에서 한글 IME로 직접 입력할 때 생기는 글자 깨짐을 우회하는 유저스크립트 프로젝트입니다. 이 문서는 무엇을 개발할지 정리한 개발 문서이며, 아직 구현은 시작하지 않았습니다.

## 해결할 문제

GitBook 편집기(`app.gitbook.com`)에서 사람이 한글 IME로 입력하면 아래 증상이 나타납니다. 증상은 변경 요청 편집 화면의 본문과 블록 코멘트 입력창에서 모두 확인했습니다.

| 위치 | 조건 | 증상 |
|---|---|---|
| 본문 | 줄 중간·앞쪽에서 "단어 단어 "처럼 스페이스가 든 한글 입력 | 스페이스가 사라지거나("바 사 " → "바사 ") 글자가 줄 끝에 붙음 |
| 코멘트 입력창 | 입력 후 커서를 앞으로 옮겨 추가 입력 | 마지막 글자가 낱자로 깨지고("요" → "ㅛ"), 새 글자가 줄 끝으로 들어가며 순서와 스페이스가 뒤섞임 |

- 줄 끝에 이어서 입력하는 경우는 정상입니다.
- 도구가 `insertText` 이벤트로 완성된 글자를 넣는 경우는 줄 중간에서도 정상입니다. 문제는 IME 조합 이벤트(`insertCompositionText`)를 거칠 때만 나타납니다.
- 사용자 확인: 크롬 확장 프로그램 끄기, 맞춤법 검사 끄기, 이전 버전 Microsoft IME 사용, 다른 브라우저로는 해결되지 않고, 화상 키보드로 입력해도 같습니다. 이 항목은 제작자가 직접 확인한 것이며 자동 시험으로 재확인하지 않았습니다.
- 환경: Windows 11, 최신 Chrome, Microsoft 한글 IME.

원인은 편집기가 조합 중인 글자를 다시 그리면서 커서와 입력 위치가 어긋나는 것으로 추정합니다. GitBook 소스를 보지 않았으므로 확정이 아닙니다.

## 목표와 범위

- 목표: 위 두 위치에서 한글 입력이 입력한 그대로, 커서 위치에 들어가게 합니다.
- 대상: GitBook 편집기를 한글로 쓰는 사용자(현재는 제작자 본인)입니다.
- 범위: `https://app.gitbook.com/*`의 본문과 코멘트 입력창입니다. 다른 사이트와 GitBook 공개 문서 화면은 다루지 않습니다.
- 형태: 유저스크립트 파일 1개입니다. Chrome과 Firefox의 Tampermonkey·Violentmonkey에서 같은 파일로 동작해야 합니다. 일본어·중국어 IME는 다루지 않습니다.

## 접근 방식

조합 중인 글자를 편집기가 건드리지 못하게, 조합을 먼저 확정한 뒤에 편집기가 이어받게 합니다. 모든 리스너는 `document` 캡처 단계에 둡니다.

1. **강제 확정**: 조합 중(`isComposing`)에 마우스 클릭, 방향키, Home/End, Enter, Tab, Ctrl/Alt/Cmd 조합이 들어오면 입력 이벤트가 편집기에 닿기 전에 조합을 확정합니다. 확정은 숨은 입력칸으로 포커스를 잠깐 옮겼다가 되돌리는 방식을 먼저 시험합니다.
2. **스페이스 가로채기**: 조합 중 스페이스가 들어오면 기본 동작을 막고, 조합을 확정한 뒤 일반 `insertText`로 공백을 넣습니다.
3. **코멘트 창 적용**: 본문과 코멘트 입력창은 별도의 편집 영역이므로 둘 다 대상에 넣습니다.

참고한 사례는 Obsidian 한글 입력 수정 플러그인([링크](https://community.obsidian.md/plugins/korean-input-fix))입니다. 이 방식이 GitBook에서 통하는지는 아직 확인하지 못했습니다.

한계로 예상하는 것은 다음과 같습니다.
- 줄 중간에서 새 조합을 시작할 때 편집기가 입력 위치를 잘못 잡는 문제는 1~2번으로 못 잡을 수 있습니다. 이 경우 조합 입력을 숨은 입력칸에서 끝낸 뒤 완성 글자만 넣는 방식으로 넘어갑니다.
- GitBook 업데이트로 동작이 깨질 수 있습니다.

## 성공 기준 (제안, 사용자 확인 필요)

아래 시나리오를 실제 IME 입력으로 실행했을 때 입력한 문자열과 결과가 같아야 합니다.

| # | 시나리오 | 기대 결과 |
|---|---|---|
| 1 | 본문, 줄 끝 입력 | 입력한 그대로 |
| 2 | 본문, 줄 중간에 "바 사 " 입력 | 스페이스 2개가 모두 남음 |
| 3 | 본문, 조합 중 방향키·Home·클릭으로 커서 이동 | 조합 글자가 낱자로 깨지지 않음 |
| 4 | 코멘트 입력창, 입력 후 커서를 앞으로 옮겨 추가 입력 | 새 글자가 커서 위치에 순서대로 들어감 |

## 검증 방법

사람이 입력하는 경로를 재현해야 하므로, 도구가 완성된 글자를 넣는 방식으로는 검증하지 않습니다.

- Windows에서 Microsoft 한글 IME가 켜진 상태로 Chrome에 가상 키 입력(`keybd_event`)을 보냅니다. 이 방식은 IME를 거쳐 `insertCompositionText` 이벤트가 발생하는 것을 확인했습니다.
- 페이지에 `beforeinput`·`compositionstart`·`compositionend` 로거를 붙여 이벤트 순서와 최종 문자열을 기록합니다.
- 같은 시나리오를 스크립트 없이 먼저 실행해 증상이 재현되는지 확인하고(대조군), 스크립트를 켠 결과와 비교합니다.
- 시험은 변경 요청의 초안 페이지에서만 하고, 발행·병합하지 않습니다.
- Firefox와 Violentmonkey는 사용자 환경에서 직접 확인해야 합니다.

## 예정 구조

```text
gitbook-hangul-ime-fix.user.js   유저스크립트 본체(파일 1개)
tools/                           IME 키 입력 전송 스크립트와 시나리오 로거(검증용)
docs/                            재현 기록, GitBook 제보문
```

## 정해야 할 것

1. 성공 기준 표의 시나리오와 합격선을 확정합니다.
2. `AGENTS.md`의 성공 기준·하지 않을 것·실행과 검증을 위 내용으로 갱신합니다.
3. 검증 스크립트가 Windows 전용이므로, 저장소의 플랫폼 중립 규칙의 예외로 둘지 정합니다.
4. 문의문(GitBook 지원팀용 영문 제보문)을 `docs/`에 보관할지 정합니다.
